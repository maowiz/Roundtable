ROUNDTABLE // MEMORY CONTROL SYSTEM

How Roundtable controls what each AI remembers

AI models have no memory between calls. So the memory lives in the app, on your PC. For every single call the app packs a sealed envelope with only what that step allows. The AI reads it, replies, and forgets everything.

A / THE LIFE OF ONE CALL · happens 21 times in a 4-agent run
01 · STOREMemory vaultrt-ledger · SQLiteHolds everything: every answer, review, cost. Stays on your PC.
02 · FILTERGatekeeperrt-envelopeTakes out only what this step allows. Names become codes. Order is shuffled.
03 · SEALSeal & recordrt-envelope + rt-ledgerEnvelope gets a fingerprint (SHA-256) and a copy is saved before it is sent.
04 · THINKThe AIrt-adapters → OpenRouterStarts with a blank memory. Sees the envelope only. Replies, then forgets.
05 · CHECKReply checkerrt-schemasReply must follow the format and may only mention codes it was given.
06 · SAVEBack to vaultrt-ledgerChecked reply saved. It becomes material for the next step's envelopes.

C / THE 5 MEMORY RULES · enforced by code, not by asking the AI
01 BLANK MEMORY

Every call is a brand-new conversation. Nothing carries over between calls or runs.

02 CODE NAMES

Authors become codes like A-7K2M9QXP. Model names inside the text are scrubbed too.

03 SHUFFLED

Reviews and improved answers arrive in random order, so position gives nothing away.

04 CHECKED

A reply that mentions a code it was not given is rejected by rt-schemas.

05 PROVABLE

Every envelope is fingerprinted and saved. We can show exactly what each AI saw.

In one line: the AI has no memory; the app is the memory, and it gives each AI only what that step needs.
